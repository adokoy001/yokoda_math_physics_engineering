# 形式意味論・ゲーム理論の深掘りメモ

## 比較した候補

1. **G04 → 評価が変わる複数最適化器の停止・循環予算。** 実務で仕様・評価器が改訂される状況に最も直接つながる。固定評価の「二度と戻らない」から、時間変動時に「戻るにはどれだけ評価の変動が要るか」へ。以下で一般補題、G04からの系、反例、古い評価の補正まで証明した。数学は初等的なポテンシャル差の望遠鏡和なので、独立の新原理と主張しない。
2. **A0–A3 → 将来の最適化可能性を保つ候補キャッシュ。** 形式意味論の固有名称を外し、「候補を消した後も、将来の要求部分集合を少数の候補で処理できるか」と捉える。要件別テスト資産・query plan・実装候補に応用候補がある。2026 PODS の Coresets for Robust Query Optimization が明確な需要先。既存 A0 の最悪将来損失は元候補一個の担当集合だけで証明書が得られるため、全将来列挙を不要にする診断器として実装しやすい。類似 coreset に一般の集合被覆比が自動適用されるわけではない。
3. **A2–A3 → 将来損失を予算化した削除ポリシー。** 初期最小圧縮ではなく、記憶数と再最適化損失のPareto曲線を最適化する。2資源乱択版 C1–C3 は既に厳密解があるので、需要の分布・到達制約・重み付けのいずれかを導入する方が自然。一般化だけでは既知 universal/robust coreset と重複しやすい。
4. **G05–G07 → 複数の監査パターン制限。** 単一制限の厳密解から強正則グラフの2点制限の隣接/非隣接分類へ。ただしユーザーの大規模AI開発への直結度は上二件より低い。

## D1：時間変動ポテンシャルの進捗予算（直接導出した補題）

状態集合 X は任意の集合でよい。時刻 t=0,…,N−1 の関数 W_t:X→R と状態列 x_0,…,x_N を置く。ここで時刻は採用された変更の番号としてよい。osc(f)=sup_X f−inf_X f と定義し、以下の右辺は有限と仮定する。

R=osc(W_0), V_N=Σ_{t=1}^{N−1}osc(W_t−W_{t−1}).

このとき

Σ_{t=0}^{N−1}[W_t(x_{t+1})−W_t(x_t)] ≤ R+V_N.

さらに x_N=x_0 なら右辺は V_N だけにできる。

**証明。** D_t=W_t−W_{t−1} と書くと厳密な恒等式

Σ_t[W_t(x_{t+1})−W_t(x_t)]
=W_0(x_N)−W_0(x_0)+Σ_{t=1}^{N−1}[D_t(x_N)−D_t(x_t)]

が成り立つ。各差をその関数の振幅で上から抑える。閉路なら最初の差は0。□

任意の時刻依存定数 c_t を W_t に加えても R,V_N,進捗は変わらない。この不変性のため、全状態に同じ点数を足す評価器の再校正は変動予算を消費しない。通常の sup 絶対変動よりこの用途に適合する。

**係数の鋭さ。** 初期振幅項は固定された二状態ポテンシャルで等号。変動項の係数も下げられない。X={a,b,c}, W_0=(0,1,1), W_1=(0,1,2), 経路 a→b→c なら進捗和2=R1+V1。閉路版は X={a,b}, W_0=(0,1), W_1=(1,0), a→b→a で進捗和2=V2。

この補題は有限ゲームも線形共有誤差も必要としない。一般の可変ポテンシャルに対する会計恒等式であって、一般に未知の目的関数を発見するアルゴリズムではない。

## D2：G04から得られる停止保証

有限ゲームの有効プレイヤー集合 I≠∅ を固定する。各時刻・状態で

U_{i,t}(s)=Φ_t(s)+⟨a_i,h_t(s)⟩, ||h_t(s)||≤ε.

固定閾値 γ_i≥0 は全 i,j∈I について γ_i+γ_j≥2ε||a_i−a_j||_* を満たすとする。W_t(s)=max_i[U_{i,t}(s)−γ_i/2] と置けば、既存G04の同じ区間論法により

U_{i,t}(s)−γ_i/2 ≤ W_t(s) ≤ U_{i,t}(s)+γ_i/2.

従って、時刻 t に i_t が変更 x_t→x_{t+1} を採用すると

W_t(x_{t+1})−W_t(x_t) ≥ ΔU_{i_t,t}−γ_{i_t}.

D1から、**閾値を超えた改善幅の総和**は

Σ_t[ΔU_{i_t,t}−γ_{i_t}] ≤ R+V_N.

各採用について ΔU_{i_t,t}>γ_{i_t}+η, η>0 を要求すると Nη<R+V_N。V_∞<∞なら採用回数は有限。閉路なら Nη<V_N。

これは採用回数を抑えるだけで、待ち時間、未採用提案数、最終コードの正しさ、大域最適性を保証しない。同一評価器バージョンで実際の採用前後を比較することが必要。評価の変更が無限の総変動を持つなら停止は結論しない。状態集合の有限性はD2の既存設定に合わせたものだが、D1から直接使うなら初期振幅と変動予算が有限であれば無限集合も扱える。

## D3：総変動有限だけでは停止しない（反例）

X={0,1}、一人、γ=0、U_t(0)=0、U_t(1)=(-1)^t 2^(−t)。x_t=0 (t偶数), x_t=1 (t奇数) として常に逆の状態へ変更する。

毎回の改善は 2^(−t)>0。それでも経路は永遠に0と1を往復する。初期振幅は1、t≥1の変動振幅は3·2^(−t)、その総和は3。評価は一様に0へ収束する。

従って「評価が一様収束する／総変動が有限なら、厳密改善を採用するだけで停止」は偽。D2の η>0 を省けない。一般には有限の進捗総量から有限の回数は出ない。

## D4：古い評価に基づく提案の補正

時刻 τ の評価 U_{i,τ} で現在の実際の前後状態 s,t を比較したとする。δ≥osc(U_{i,k}−U_{i,τ}) が認証されていれば

ΔU_{i,k}≥ΔU_{i,τ}−δ.

よって採用時点 k に必要な条件 ΔU_{i,k}>γ_i+η は、古い評価で ΔU_{i,τ}>γ_i+η+δ を課せば保証できる。証明は誤差関数の二点差の下界 −osc だけである。古いブランチの前後と現在のマージ結果の前後が違う場合、この式では足りず、実際の採用結果を再評価する必要がある。

## 実用化するなら

最初の実験は、LLM評価を真の目的とみなすのではなく、実行可能な評価項目（検証済みテスト、推論時間、依存量など）を持つ小規模の複数コード改善器に限定する。評価バージョン・同一状態の再評価差・採用前後の状態hashを残し、単なる採用数上限の有効性と、γ/ηが有用な変更を止めすぎる率を測る。ユーザーの一般の「願い」を有限次元線形共有誤差モデルが網羅したとは言わない。
